# Assignment template

Format: `opencode-luuna.assignment/v1`. **Template only.**

- Assignment ID / task ID / ticket / attempt index:
- Role and assignment kind (investigation/setup/implementation/validation/design/review):
- Objective and acceptance criteria:
- Exact approved plan revision and user confirmation reference:
- Repository IDs, observed bases/candidates, worktree owner:
- Allowed paths and operation classes; forbidden changes:
- Dependencies and exact package/artifact/client/endpoint bindings:
- Current instructions, required skills, relevant reference sections:
- Baseline evidence and approved recipes (command, args, cwd, environment):
- Context manifest and authorized artifact locations:
- Remaining task and aggregate repair/time/spending budgets:
- Required structured result and stop conditions:

Return: assignment/task/role, source/candidate identity, status, observed findings,
changed paths, actual check/artifact references, assumptions, blockers, next action,
and any proposed (not automatically persisted) lesson. Do not delegate, expand
scope, edit policy, publish, merge, or reset attempts.

For independent review: new session; approved scope, acceptance criteria, current
code/diff, source identities, bindings, and execution records only. No
implementation transcript, session fork, or implementer self-assessment as proof.
